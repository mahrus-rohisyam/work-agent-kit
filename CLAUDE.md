# Work agent kit

A workspace for two kinds of work:

1. **Project management**: reports, minutes of meeting, Jira, presentations, email follow-up.
2. **Marketing**: content for one or more products ("brands"), made with Claude and code only.

Who the user is, their organization, language and preferences: `profile.md` (not in git).

@profile.md

If `profile.md` does not exist, suggest `/setup` before the first report or campaign; do not guess its content.
Workspace rules (security, confirmations) are in `.github/copilot-instructions.md` and apply here too.

## References

- Read `references/INDEX.md` first, then only the relevant files in `references/distilled/`.
- Do not open, glob or grep `references/raw/` unless the user asks or says "process new references".
- "Process new references": read the raw files not yet marked as processed in the index, write or update a
  summary in `distilled/` (format: `distilled/_TEMPLATE.md`), and update the tables in `INDEX.md`.
- Feedback about a type of output goes in the *Rules* section of the matching `distilled/` file.
- `distilled/` is in git. Leave client names, people and confidential figures out of it.
- Never read a video or a folder of images directly. Run the tool, then read its small output:
  - Video: `tools/video_study.sh <video>` writes `references/distilled/videos/<name>/`. Read `meta.txt`,
    `cuts.txt`, `transcript.srt`, then `hook.png`, `shots.png` (and `timeline.png` only if needed). Fill
    `breakdown.md`. Later jobs read only `breakdown.md`.
  - Images/icons: `tools/image_sheet.sh <dir>` makes one contact sheet and a file order list. SVG: read as text.
- Patterns seen across several reference videos go to `playbook/what-works.md` (dated, with sources).
  Reference videos are for structure and pacing only; never copy their footage, people or claims.
- Transcripts use the ffmpeg `whisper` filter (ffmpeg 8+) with a model in `tools/whisper-models/`
  (`ggml-small.bin`, multilingual, from huggingface.co/ggerganov/whisper.cpp). Not in git.

## Reports, decks and documents

- Anything that must follow the organization's template is built with the `doc-builder` subagent, which writes
  a JSON spec and runs `tools/docs/build_deck.py` or `build_doc.py` through `uv`. Formats: `tools/docs/README.md`.
- Output: decks in `documents/`, Word documents in `outputs/`.

## Marketing

No paid tools, no GPU, no generative image/video models. Videos and images are React compositions
rendered by Remotion from real product footage. Music is generated by code.

| Path | What |
|---|---|
| `ANTI-SLOP.md` | Shared quality rules for copy, visuals and motion. Read before writing anything. |
| `brands/<brand>/brand.md` | Positioning, audience, voice, provable messages, channels, checklist |
| `brands/<brand>/lexicon.json` | Words to ban/spell, punctuation rules (read by `slop_check.py`) |
| `brands/<brand>/tokens.json` | Colors, font, logo files, motion timings |
| `brands/<brand>/assets/`, `stills/`, `footage/` | Logos; full-resolution frames; demo videos (footage is not in git) |
| `brands/<brand>/learnings.md` | Feedback from the user, turned into rules. Read before every job. |
| `brands/<brand>/ideas.md`, `radar.json` | Content ideas from product changes (`/content-radar`) |
| `brands/<brand>/briefs/<yyyy-mm-slug>/` | `brief.md` + one render spec JSON per asset |
| `brands/<brand>/out/` | Rendered files (safe to delete and re-render) |
| `brands/_template/` | Copied by `/new-brand`. `brands/example/` is a made-up brand for test renders. |
| `playbook/` | Shared, dated knowledge: channel specs, what works, tool notes, change log |
| `video/` | Remotion project. Compositions: `vertical` 1080×1920, `landscape` 1920×1080, `square` 1080×1080, `showcase-vertical` / `showcase-landscape`, `tour` (1920×1080), stills `post` 1080×1350, `og` 1200×630, `cover` 1920×1080. Schemas in `video/src/`. |

### Rules

1. **Each brand has its own voice.** Never carry phrasing, colors or claims from one brand to another.
   Shared rules are only `ANTI-SLOP.md` and `playbook/`.
2. **Claims need proof.** Every claim maps to the product's docs, changelog or a demo video listed in
   `brand.md`. Never invent numbers, customers, prices or quotes.
3. **Real footage only.** No AI-generated people, UI or testimonials.
4. **Lint before render:** `tools/slop_check.py --brand <brand> <spec.json>…` must be clean.
5. **Look at the output.** After a render, check it with `tools/frames.sh <file>` and read the image.
6. **Learn.** When the user gives feedback, record it with `/retro` in the same session.
7. One render at a time. `RENDER_CONCURRENCY` (default 2) sets the CPU use.
8. Remotion is free for individuals and companies of up to 3 people; larger companies need a license. Flag it.
9. Product repos are read-only from here. Ask before changing one.

### Commands

```sh
tools/render.sh example hello                     # lint + render every spec in the brief folder
tools/frames.sh brands/example/out/hello/tour.mp4 # contact strip for review
python3 tools/make_music.py video/public/music/<name>.m4a --seconds 40 --mood calm --seed 1
cd video && pnpm studio                           # live preview in a browser (port 3000)
```

### Scheduled jobs (optional, Linux)

`tools/scheduled.sh radar` (weekly) and `refresh` (monthly) run Claude headless with no Bash, at idle CPU
priority. They write only to `brands/**` (radar) or `playbook/**` (refresh); rule changes go to "Proposed
changes" for the user. Logs: `logs/`. The user installs the cron lines:

    30 3 * * 1 <repo>/tools/scheduled.sh radar
    0 4 1 * * <repo>/tools/scheduled.sh refresh
